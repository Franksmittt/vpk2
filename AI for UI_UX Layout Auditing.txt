Architectural Frameworks for AI-Driven UI/UX Design: Integrating Editorial Layouts and Recursive Code Audits in Next.js
Introduction to the Automation of Editorial Interfaces
The integration of artificial intelligence into software development has fundamentally altered the pace at which code is generated, yet a pervasive challenge remains: the translation of functional logic into cohesive, aesthetically sound user interfaces. Large Language Models (LLMs) and AI-assisted code editors, such as Cursor, frequently produce interface layouts that suffer from disjointed spacing, erratic component sizing, and an overall lack of visual rhythm.1 This phenomenon, often referred to colloquially as "vibe coding," occurs when development relies heavily on AI generation without enforcing a rigorous underlying design system.2 The result is a user interface that, while functionally sound, lacks the polished, intentional flow characteristic of professional editorial design, such as that found in high-end magazines or newspapers.4
When developers delegate the construction of a Next.js application to an AI agent, the machine inherently lacks spatial awareness. It processes code sequentially as text tokens, lacking the intrinsic visual intuition that a human art director uses to balance a page. Consequently, the AI will often generate layouts where text and imagery collide unpredictably.1 A common manifestation of this failure occurs when an AI inserts an excessively large image alongside a minuscule paragraph of text, or conversely, generates an overwhelming wall of text punctuated by an inappropriately small graphic.5 Furthermore, AI tools frequently struggle to maintain structural integrity across varying viewport sizes, leading to responsive designs that collapse or behave erratically on mobile devices.1
To rectify the inconsistencies inherent in AI-generated user interfaces, it is necessary to impose strict architectural frameworks upon the AI's contextual understanding. By enforcing mathematical grid systems, precise image-to-text ratios, and modality-specific responsive rules, developers can constrain the AI to generate layouts that adhere to classical editorial standards.5 Furthermore, a single prompt is rarely sufficient to achieve production-quality design.9 Instead, a multi-tiered approach utilizing recursive auditing workflows—where specialized AI sub-agents iteratively review the codebase component-by-component—is required to ensure that spacing, typography, and structural integrity remain consistent across the entire application.10
This report provides an exhaustive analysis of the strategies required to configure an AI coding environment to think and design like an editorial art director. The analysis encompasses the mathematical foundations of print and digital layout, the integration of these principles into modern frontend frameworks such as Next.js and Tailwind CSS, and the deployment of advanced prompting architectures to execute recursive UI/UX and codebase audits.
The Philosophy of Editorial Design in Digital Spaces
Editorial design is the discipline of orchestrating text, imagery, and negative space to communicate a narrative efficiently and beautifully.4 In the context of traditional publishing—such as newspapers and glossy magazines—an editor does not merely place content onto a page; they direct the reader's cognitive flow.6 This deliberate pacing of information relies on established psychological principles regarding visual hierarchy, reading patterns, and the mitigation of cognitive overload.8
When transitioning these principles to a digital medium, the fundamental objective remains identical: to create a predictable, harmonious system that guides the user's eye naturally from one point of interest to the next.8 However, the digital canvas is fluid. A magazine layout is fixed in its dimensions, whereas a Next.js web application must seamlessly adapt to an infinite spectrum of screen sizes and device orientations.14 This fluidity is precisely where AI-generated designs typically fail.1 Without explicit instructions, an AI treats the web browser as a blank, unconstrained void, placing div containers and React components arbitrarily.8
To force an AI to replicate the nuance of an editorial layout, it must be programmed to understand the page not as a collection of isolated React components, but as a unified composition governed by rigid, interconnected rules. The AI must be taught that every element added to the DOM exerts a visual "weight" that must be counterbalanced.8 A large, high-resolution hero image carries massive visual gravity; if it is not balanced by appropriately scaled typography or negative space, the layout feels structurally unsound.15
Implementing this editorial philosophy requires moving beyond basic CSS styling and establishing a comprehensive architectural logic. The AI must be instructed to utilize grid systems to constrain horizontal placement, baseline rhythms to dictate vertical spacing, and proportional heuristics to govern the relationship between textual and visual elements.8 Only by embedding these principles deeply into the project's configuration files and the AI's system prompts can the developer expect the machine to output an interface that mimics the polish of a professional publication.
Mathematical Foundations of Grid Architecture
The foundation of any sophisticated editorial layout is the grid system. Grids serve as the graphic backbone of a design, providing a structured, mathematical environment where elements can be predictably aligned.4 Historically, grid systems were relied upon by forward-thinking artists in the modernist movement and have served as the foundation for typographic progress for centuries.12 When instructing an AI to generate user interfaces, establishing the parameters of this grid is the single most critical step in preventing the chaotic, unaligned placement of text and imagery.8
Typologies of Grid Architecture
Grid systems function on two distinct levels: the unit level, which dictates the smallest indivisible cell of the layout (e.g., a 20x20 pixel square), and the column level, which groups these units to create visual structure.8 To effectively prompt an AI, the developer must specify exactly which type of grid architecture the AI should construct. There are four primary typologies of grid systems utilized in graphic design, each serving a distinct editorial purpose.12

By explicitly instructing the AI to utilize a canonical 12-column modular grid, designers establish permanent "anchor points".8 A 12-column grid is highly divisible (by 1, 2, 3, 4, 6, and 12), providing the AI with the mathematical flexibility to mix long-form text (spanning perhaps 8 columns) with smaller, floating elements, such as pull-quotes, author portraits, or informational sidebars (spanning the remaining 4 columns).8

Vertical Rhythm and the Baseline Grid
While horizontal grids govern column widths and the lateral placement of components, vertical rhythm governs the spacing and arrangement of elements as a user descends down the page.8 AI code generators frequently violate vertical rhythm by injecting arbitrary, disconnected margin values (e.g., applying mt-4 to a paragraph, followed by mb-7 to a header, and py-2 to an image).1 This creates a jarring, disjointed scrolling experience that breaks the illusion of a professionally curated publication.
The core principle required to solve this is the baseline grid.8 A baseline grid ensures that the bottom of every line of text, and the bounding boxes of all imagery, fall on a vertical grid set in even, mathematical increments all the way down the page.8
Vertical rhythm is determined by the complex interaction of three typographic factors: font size, line height (leading), and padding/margins.8 When prompting an AI to generate layouts, particularly in Tailwind CSS, it is imperative to enforce a strict base unit tied directly to the document's line height.
For example, if the body's base font size is set to 12 pixels with a line height of 18 pixels (representing 150% leading), the fundamental baseline grid increment becomes exactly 18 pixels.8 Consequently, all vertical spacing elements across the entire application must be strictly enforced as multiples of this 18-pixel unit.8
* Standard paragraphs must be configured with a bottom margin of exactly 18 pixels.8
* An h1 heading might utilize a font size of 24 pixels, a line height of 36 pixels (two baseline units), and a bottom margin of 18 pixels.8
* An h2 heading might utilize a font size of 18 pixels, a line height of 18 pixels, and a bottom margin of 18 pixels.8
The mathematics must account for every pixel. If an AI generates a callout box component with a 1-pixel border, the padding must be adjusted algorithmically to compensate so the total vertical footprint remains a multiple of 18. For example: 8px top padding + 8px bottom padding + 1px top border + 1px bottom border = 18 pixels.8 By establishing rigorous rules regarding baseline grids, the developer forces the AI to output CSS classes that maintain absolute structural integrity, ensuring that text across parallel columns aligns perfectly on the horizontal axis.8
Advanced Grid Behaviors in Modern CSS Architecture
To translate these historical print methodologies into modern Next.js environments, the AI must be deeply contextualized in contemporary CSS Grid and Flexbox architectures.8 Older methodologies, such as using floats and clearfix hacks, are fundamentally incompatible with responsive, dynamic data and will severely degrade the AI's output.8
The Role of Flexbox in Component Design
Flexbox provides a "content-out" approach, making it the ideal architecture for single-axis alignments, such as navigation bars, horizontal lists, or grouped form elements.8 When setting display: flex, the AI must be instructed to manage spatial proportions through precise control of the flex properties.
Flexibility is managed through flex-grow (dictating how items expand to fill excess space), flex-shrink (dictating how items compress when space is lacking), and flex-basis (the starting dimensional size).8 AI tools often haphazardly apply flex-1 to elements, causing unpredictable stretching. To enforce editorial control, the AI must be given strict rules on cross-axis alignment (align-items) and main-axis distribution (justify-content), ensuring that elements are spaced mathematically using values like space-between or space-around.8 Furthermore, the AI must account for flex wrapping (flex-wrap: wrap); when items wrap to a new row, they instantiate a new flex container, which can break vertical alignment with the row above if not carefully constrained.8
Two-Dimensional CSS Grid Implementation
While Flexbox is excellent for micro-components, CSS Grid is the undisputed standard for macro-layouts, allowing for two-dimensional manipulation that perfectly mirrors the modular grids of print magazines.8
When instructing an AI to build a page wrapper, explicit track sizing must be mandated. Instead of relying on the browser's implicit grid behavior, the AI should utilize the fr (fractional) unit to divide available space predictably.8 For instance, providing the AI with the exact repeat syntax (grid-template-columns: repeat(12, 1fr)) guarantees the 12-column foundation.8
Crucially, the AI must be instructed to utilize the Box Alignment Module to govern the "gutters" of the digital magazine layout.8 Gutters—the negative space between columns—are vital for preventing text or images from different columns from visually bleeding into one another.8 Setting gap values in Tailwind (e.g., gap-x-6 gap-y-8) must be done consistently.19 By combining display: grid with default alignment values like align-items: stretch, the AI can effortlessly generate equal-height columns, a task that was notoriously difficult in previous eras of web design and remains a hallmark of polished editorial layouts.8
Harmonizing Image-to-Text Proportions
A primary grievance regarding AI-generated layouts is the machine's inability to intuitively balance visual weight. As noted in the analysis of raw AI outputs, layouts frequently feature massive, screen-filling images accompanied by a single, diminutive line of text, or conversely, an exhausting wall of text interrupted by an inadequately small thumbnail.1 In professional editorial design, cognitive psychology and visual hierarchy dictate strict, quantifiable rules for image-to-text ratios.5
Information Density and the 60/40 Paradigm
The human brain processes visual information approximately 60,000 times faster than it processes text, interpreting complex images in as little as 13 milliseconds.15 Consequently, an interface dominated entirely by text creates excessive cognitive friction, appearing daunting and academic, while an interface dominated entirely by imagery lacks semantic depth, context, and accessibility.5
The industry standard for achieving aesthetic and cognitive equilibrium is the 60/40 rule.20 This paradigm dictates that an optimal layout should comprise approximately 60% visual content (including images, graphics, icons, and intentional white space) and 40% textual content (headlines, body copy, calls-to-action).20 While this rule is most strictly enforced by spam-detection algorithms like SpamAssassin in email marketing to prevent deliverability penalizations, it serves as an equally potent heuristic for web layout aesthetics.20 Depending on the severity of the content, some best practices allow for an image-to-text ratio incorporating 60-80% text alongside 20-40% images for highly technical or educational whitepapers.5
Quantitative Heuristics for AI Scaling
To enforce this harmonious flow within an AI's logic, qualitative descriptions must be translated into quantitative rules based on word count. An AI cannot simply "make it look good"; it must compute the density of the content provided.
Research analyzing millions of digital articles indicates that the optimal distribution of imagery is approximately one image for every 150 to 300 words.22 Incorporating visuals at this specific frequency breaks up long text blocks, provides the reader with necessary visual rest periods, and has been shown to double user engagement compared to text-dense alternatives.6
Furthermore, when prompting an AI to design a complex article layout or a multi-section homepage, a maximum text limit must be imposed to ensure adequate real estate remains for photography and negative space. Print editorial rules suggest a strict maximum of 700 to 750 words per two-page spread.23 If an AI is generating a web section that mimics a spread, and the provided text exceeds 750 words, the AI should be programmed to autonomously truncate the text, move it to a subsequent section, or suggest the implementation of an accordion or tabbed interface to preserve the 60/40 visual balance.23 Without this constraint, the AI will simply stretch the container vertically, destroying the grid proportions.

Responsive Image Heuristics and Scaling Logic
Digital layouts, unlike printed magazines, are highly fluid and continuously re-render based on the user's hardware. Therefore, the AI must be instructed to treat responsive image scaling not as an afterthought, but as a core computational component of the editorial flow.26 As the viewport narrows, the mathematical relationship between the image and the surrounding text fundamentally changes, requiring different geometric rules.27
A robust responsive image strategy requires the AI to implement the HTML <picture> element and the srcset attribute natively.28 This provides the user agent (the browser) with a comprehensive list of available image options tailored to different screen resolutions, orientations, and pixel densities (DPI).28
The AI must be trained to generate responsive components that execute conditional logic similar to the following heuristic framework:
* Widescreen (Viewports > 66em): Display the image at full width, spanning all 12 columns of the grid, utilizing the highest resolution asset available to satisfy high-DPI displays.27
* Tablet/Standard (Viewports between 44em and 66em): Display the image at exactly half the width of the screen, floating it to the left or right of the text to mimic a classic two-column print layout. The AI must select a mid-resolution image from the srcset to optimize load times.27
* Mobile (Viewports < 44em): Collapse the image back to a full-width block element. Attempting to float an image next to text on a narrow mobile screen forces the text into an illegible, narrow column. The AI must stack the elements vertically to preserve readability.27
Furthermore, the introduction of container queries (e.g., @container and @max-* in Tailwind CSS v4) represents a paradigm shift for AI-generated code.31 Historically, AI models struggled to style isolated components because media queries rely on the global viewport size. Container queries allow the AI to adapt image sizes and typography scales based solely on the width of the component's immediate parent container.31 This permits a sidebar component to autonomously maintain its specific 60/40 image-to-text ratio regardless of where the developer eventually places it within the broader macro-layout, significantly enhancing the modularity and reusability of the AI's output.31
Configuring the AI Environment: Next.js and Tailwind CSS
An AI agent cannot intuitively guess a developer's intended design language; it operates strictly within the confines of its provided context window.32 If the environment is not meticulously configured, the AI will hallucinate standard HTML styling, resulting in the janky, unpolished layouts frequently reported by users.1 To bridge the gap between abstract editorial principles and functional React code, the project environment must be locked down using .cursorrules files and strict framework conventions.34
Defining the .cursorrules Architecture
In AI-assisted IDEs like Cursor, Windsurf, or GitHub Copilot, the .cursorrules (or .windsurfrules) file acts as the foundational system prompt, persistently feeding operational parameters into the LLM's context with every request.31 To ensure UI consistency, this file must move far beyond basic syntax preferences (like single vs. double quotes) and explicitly dictate the layout heuristics discussed previously.
A well-architected .cursorrules file for a Next.js and Tailwind CSS project must enforce several non-negotiable directives 31:
1. Strict Utility-Class Adherence: The AI must be explicitly forbidden from using inline CSS (style={{}}) or writing external custom CSS files unless addressing highly specific edge cases (like complex animations). All styling must be executed through standard Tailwind utility classes to ensure a unified, predictable design language.31
2. Design Token Standardization: The AI must use predefined design tokens for spacing, typography, and color. By referencing a shared configuration file (tailwind.config.js or the modern @theme directive in Tailwind v4), the AI is restricted to utilizing only approved multi-scale increments.31 The rules must enforce that the AI relies strictly on design token multiples (e.g., 4px, 8px, 16px) to preserve the vertical baseline rhythm, strictly prohibiting arbitrary spacing values.38
3. Component Modularity: To avoid code duplication and massive, unreadable monolithic files, the rules must enforce the extraction of repeating UI elements into reusable functional React components. The AI should prioritize iteration and modularization over code duplication.35
4. Typographic and Functional Naming: Component files must follow strict lowercase, dash-separated naming conventions (e.g., components/auth-wizard/new-component.tsx), while event handlers must utilize action-oriented prefixes (e.g., handleClick, handleKeyDown).35
Leveraging Tailwind v4 Innovations
The introduction of Tailwind CSS v4 provides advanced, dynamic features that significantly enhance an AI's ability to generate complex, magazine-style layouts effortlessly.31 The AI rules engine must be explicitly updated to utilize these modern paradigms, or it will default to outdated v3 syntax.
* Dynamic Spacing and Values: Tailwind v4 accepts arbitrary spacing values natively without requiring the traditional bracket syntax in all cases.31 The rules should instruct the AI to group related elements with matching gap values to ensure consistent component spacing across grid systems.39
* Modern Color Spaces: The AI should be instructed to utilize modern color formats such as oklch for vastly improved color gamut support, defining these root variables within the :root scope for global accessibility.31
* Advanced Modifiers: For advanced visual effects akin to print publication overlays, the AI can be guided to use v4 utilities like rotate-x-*, rotate-y-*, and scale-z-*, combined with arbitrary value modifiers (not-*, starting) for complex hover, focus, and entrance states.31
Modality-Specific Generation
A frequent mistake in AI prompt engineering is instructing the model to "make the layout responsive" in a single, broad pass.38 Optimizing for desktop and mobile simultaneously overloads the AI's spatial reasoning capabilities, often resulting in layouts that compromise both modalities.38
Instead, the AI rules must dictate that desktop and mobile optimization are treated as separate, distinct modalities. The workflow should dictate a strict mobile-first approach.35 The AI must first write the foundational HTML styled exclusively for the smallest viewport using standard utility classes.14 Only after the mobile layout is mathematically sound should the AI apply responsive prefix modifiers (sm:, md:, lg:) to adapt the layout for wider desktop screens.14
Prompt Engineering for UI/UX: The Editorial Persona
The transition from a mediocre, structurally unsound interface to a polished, professional layout requires a fundamental shift in how the developer communicates with the AI agent. The quality of the AI's output is directly correlated to the vocabulary, constraints, and operational persona defined in the user's prompt.32
The Fallacy of One-Shot Generation
Attempting to compress the entire design process—from rough wireframe layout to typography, color theory, interactions, and accessibility audits—into a single, monolithic prompt is a guaranteed recipe for failure.9 Professional editorial design is an iterative, sequential process.9 Therefore, the AI workflow must replicate this phased methodology.
The developer must interact with the AI using an iterative enhancement workflow.38 The process begins by constructing the structural components (the scaffolding) without advanced styling. The initial prompt should focus purely on establishing the DOM hierarchy, the CSS Grid architecture, and the image-to-text aspect ratios.7 Only after the basic structure is mathematically sound should subsequent prompts be utilized to introduce typographic hierarchy, rhythm adjustments, and subtle polish.7
Buzzword Engineering and Semantic Shortcuts
Large Language Models associate specific stylistic keywords with dense clusters of high-quality training data. Providing vague, subjective directives such as "make it clean," "make it pop," or "make it look modern" forces the AI to guess, yielding generic, uninspired, and often contradictory results.7 To achieve a specific editorial aesthetic, the prompt must utilize precise design terminology—acting as semantic shortcuts that instantly align the AI with specific visual principles.7
* Instead of requesting a "clean" interface, the prompt should demand "Minimalist, Swiss design typography, with monospace accents and high negative space." 7
* Instead of requesting a "modern" feel, the prompt should request a "Brutalist layout with heavy borders" or "Strategic glassmorphic overlays for floating modal components." 7
* When referencing structural flow, explicitly demand "asymmetrical balance," "proximity-based grouping," or "editorial grid breakage" to instruct the AI to creatively overlap illustrations outside the strict confines of the column grid.8
Furthermore, the "80/20 Prompt Rule" dictates that the vast majority of high-quality UI generation stems from clearly defining just four elements: the component type, the specific visual style, the tech stack (e.g., React with Tailwind v4), and the layout structure.7 Eliminating conversational prose and focusing entirely on these four pillars provides the AI with a strict, unambiguous operational matrix.7
"Stealing Like an Artist" Through Referential Prompting
AI models perform exceptionally well when provided with concrete reference points rather than abstract descriptions. To bypass the AI's tendency to generate generic layouts, the prompt should explicitly reference existing, highly regarded design systems.7 Instructing the AI to "Design a pricing card component utilizing the spatial pacing and typography hierarchy of the Linear issue tracker, but adapted for a magazine-style news feed" provides an immediate, recognizable pattern for the AI to emulate.1 The AI can then extract the underlying structural logic of that reference and customize it to fit the current project's specific Tailwind design tokens.7
The Recursive Codebase Audit Methodology
Even with pristine .cursorrules, advanced prompt engineering, and a strict adherence to grid mathematics, a complex Next.js application will inevitably suffer from code entropy over time. As the AI generates dozens of components across multiple sessions, it may lose context, duplicate logic, or subtly deviate from the established spacing systems, resulting in the very inconsistencies the user seeks to avoid.40
To finalize, polish, and synthesize an entire project, a recursive codebase audit is required. This is achieved through the deployment of an advanced prompt architecture—often referred to as the "Last Prompt"—which fragments the AI into multiple specialized sub-agents.11 Each sub-agent is instructed to review the entire codebase from a distinct, highly specialized, and hyper-critical perspective.11
By feeding the AI a prompt that demands it crawl through the application "page by page, component by component," the developer forces the system to reconcile its past generations with the project's global rules.10 The following four sub-agents encompass the necessary auditing workflow.
Sub-Agent 1: The UI/UX and Consistency Auditor
The first sub-agent acts as the senior editorial art director. Its explicit mandate is to recursively crawl through the codebase, analyzing every React component and Tailwind class combination for visual fidelity and compliance with the design tokens.38
This agent evaluates the visual design against strict heuristics:
* Spacing Rhythm Verification: Does every margin (m-*), padding (p-*), and gap (gap-*) value adhere strictly to the established mathematical scale? The agent must flag any arbitrary pixel values that violate the 4px/8px rhythm.38
* Grid Integrity and Alignment: Do the components align perfectly to the canonical 12-column grid? Are short elements terminating exactly on grid boundaries, and are flex containers properly constrained? 8
* Typography Hierarchy: Is the relationship between headers (h1, h2, h3) and body copy mathematically consistent? Does the text maintain the baseline grid across parallel columns? 8
* Accessibility (WCAG Compliance): The agent must audit all instances of text placed over images or colored backgrounds. It must calculate the contrast to ensure it meets the strict 4.5:1 minimum visual contrast ratio required for body text, guaranteeing legibility.11 Furthermore, it must verify that all interactive elements possess visible focus indicators for keyboard navigation, and that aria-labels and tabindex properties are properly implemented.36
Sub-Agent 2: The Traceability and Integration Auditor
The most severe functional failures in AI-generated code occur at the "seams" between components, or at the boundaries between the frontend UI and the backend data layer.11 The traceability auditor acts as a full-stack integration architect, tracking the flow of data and layout logic across the application's layers.11
This sub-agent performs a rigorous, step-by-step verification process:
1. Action Tracking: It traces every potential user action (e.g., button clicks, form submissions, navigation links) from the UI layer down through the API to the database, ensuring that the appropriate function is called without dead ends.11
2. Signature and Contract Verification: It verifies that the arguments passed from the UI exactly match the data contracts expected by the backend.11 A remarkably common AI hallucination involves mismatched parameter names and types (e.g., the frontend passing an integer as userId while the database expects a string as user_id); the traceability agent specifically hunts for these exact discrepancies.11
3. Component Nesting Drilling: Utilizing tools like Claude Code or Cursor's codebase indexing, the agent maps out every sub-component used on a specific page, verifying that deeply nested layouts do not inadvertently overflow or break their parent grid containers.10
Sub-Agent 3: The Optimization and Refactoring Engineer
AI generators possess a strong, inherent tendency toward code duplication. If an AI loses context between sessions, it will frequently solve the exact same layout problem in slightly different ways across multiple files, leading to bloated, unmaintainable CSS and React logic.11 The optimization sub-agent acts as a senior performance specialist.11
Its audit checklist includes:
* Redundancy Identification: Locating utility functions, Tailwind class combinations, or UI components that are duplicated across the repository. The agent must recommend consolidating them into a single, reusable source of truth.11
* Dead Code Elimination: Identifying and purging initial layout scaffolding, unused CSS classes, orphaned variables, or unused imports that are no longer referenced by the application.11
* Performance Bottlenecks: Evaluating the implementation of Next.js specific features. The agent ensures that React Server Components (RSC) are favored over client-side rendering (use client) wherever possible to minimize bundle size, and verifies that dynamic loading and image optimization techniques (such as Next/Image, WebP formatting, and lazy loading) are correctly deployed to optimize Core Web Vitals (LCP, CLS, FID).11
Sub-Agent 4: The Security Assessor
The final, and arguably most critical, review must be conducted from the perspective of an adversarial security expert.11 The prompt must explicitly command the AI to treat the codebase as if it were written by a careless junior developer.11 By resetting the AI's assumptions, it prevents the model from blindly trusting the code it previously generated, forcing a hyper-critical, adversarial review where every input is treated as a potential threat vector.11
The security auditor evaluates the application for severe vulnerabilities commonly found in "vibe coded" applications 3:
* Injection Flaws: Analyzing every database query, ORM execution, and data input field for susceptibility to SQL Injection, NoSQL Injection, or Command Injection.3
* Cross-Site Scripting (XSS) and CSRF: Ensuring that the UI layer properly escapes all user-generated content before rendering it, and that form submissions are protected against Cross-Site Request Forgery.3
* Authentication and Authorization: Ensuring that sensitive routes in the Next.js application are properly protected by middleware, and that user permissions and roles are rigorously enforced at the server level.3
* Input Validation: Verifying that all form inputs—especially those heavily styled by the UI/UX agent—are thoroughly validated and sanitized on the server before processing.3
* Secrets Management: Scanning the codebase to ensure no API keys, tokens, or sensitive environment variables have been hardcoded into the frontend components.3
